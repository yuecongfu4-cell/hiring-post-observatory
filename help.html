使用帮助

把你已取得的真实帖子和评论整理成可核验的研究材料。先保存记录，再审核样本；每次更新都保留清楚的数据口径。

导入材料审核与样本冻结与工作版本理解统计招聘帖文案打分器保存与恢复资料使用边界

01　从真实材料开始

可以逐条录入帖子，也可以批量导入 CSV 或 XLSX。新增真实帖子须有领英帖子链接、至少 40 字符正文、岗位类别、真实发布日期和采集时间。互动数未知时留空；正文至少 80 字符且点赞与页面评论数均已填写，才进入互动分析。草稿独立保存，不计入研究样本。

工作台不会自动访问、登录或抓取领英。填写链接只用于标记来源，不会自动取得帖子内容或评论。

逐条添加帖子与评论

  1. 点击“添加数据”，选择“真实帖子”。粘贴招聘动态链接，再填写正文、岗位、发布日期、观察时间和已知互动数。
  2. 如果招聘动态已收录，点击“载入已存帖子信息”，核对本次观察值后提交。已有数值不会自动从领英刷新。
  3. 评论在“添加数据 → 评论”中单独填写。用帖子编号或已收录的招聘动态链接关联，再粘贴评论正文。
  4. 进入“审核新增数据”，确认来源与字段后点击“通过并纳入”。切换“工作样本”查看更新后的图表。

领英 /jobs/view/ 职位详情链接可以粘贴到“相关职位详情链接”。它作为招聘动态的参考资料保存，不会单独计入动态样本；只提供链接不会自动取得职位正文或评论。

批量添加时，在“添加数据 → 批量导入”下载帖子或评论模板，填写后选择 CSV / XLSX 文件。先检查预览，再保存到待审核；请先导入帖子，再导入对应评论。

准备 CSV 或 XLSX

  • 首行填写列名，从第二行开始填写数据。一行对应一条帖子记录或一条评论记录。
  • CSV 请使用 UTF-8 编码和英文逗号分隔。正文包含逗号、引号或换行时，请用英文双引号包住单元格，正文内的双引号写成两个双引号。
  • XLSX 只读取工作簿中的首个工作表。请把要导入的数据放在该表，避免合并单元格、空列名和重复列名。
  • 不会执行公式。XLSX 公式仅读取文件中已有的缓存结果；没有缓存时按空值读取。导入前将公式另存为值更便于核验。
  • 每个文件最多 100 MB、100,000 行数据。XLSX 解压后总内容最多 256 MB；本机 IndexedDB 会保存完整工作区，并已通过 20,000 条帖子容量测试。数据特别大时仍建议按批次导入，便于中断后恢复。

列名与日期

中英文列名可兼容使用。请优先使用工作台提供的模板列名，保留帖子 ID，便于后续补充同一帖子的互动数和评论。

不需要作者姓名或个人主页。日期建议填写带时区的 ISO 格式，例如 2026-11-18T10:00:00+08:00。XLSX 中已识别的日期列会将 Excel 日期序号转换成 ISO 时间。不要把无法确认的日期或缺失的互动数写成 0；留空并在审核前补齐。

02　记录与可用样本有不同口径

记录是工作台里保存的材料。可用分析样本还需要完成必要字段核验并通过审核。导入成功只代表材料已读入，不能直接把全部导入行数写成研究样本量。

  1. 核对正文、来源、帖子 ID、发布时间与采集时间，检查互动数是否与同一次观察一致。
  2. 补充缺失材料，处理重复记录，再确认审核。
  3. 切换到工作样本查看更新后的统计；保留缺失项的记录可以以后继续补充。

同一帖子后续采集到新的互动数时，继续使用相同帖子 ID。它是同一帖子的更新观察，不应增加独立帖子数。新增或修改的材料需要重新核验后再纳入工作样本。

更新时须保留同一条帖子的规范链接，并填写较新的观察时间。工作台会列出前后互动数，审核通过后替换工作样本的快照；已经冻结的报告不变。相同链接不会增加帖子数，正文相同的重复记录也不会新增。

评论通过所属帖子 ID 关联到帖子。评论总数不等于已取得的评论正文数；只有数字、链接或空正文，不能当作可供文本分析的评论样本。

03　区分冻结报告与工作样本

冻结报告保留既有研究版本及其统计口径，新增材料不会改写这份基准。需要复核既有报告时，使用冻结版本。

工作样本用于继续录入、补充、审核和分析。完成审核后，工作版本的统计随当前有效材料更新。

记录分析结果时，请同时注明页面所选版本、筛选条件和观察时间。不要将冻结报告中的数字与新增工作样本的数字混成同一个样本口径。

04　理解统计与文本线索

工作台描述已有样本，不提供互动量预测。计数、分布和对比反映当前版本内已经保存并审核的数据，不能自动推断整个平台或未来表现。

按发布至采集时长比较

发布至采集时长指从发布到互动数采集时经过的时间。页面按 0 至 7 天、8 至 30 天、31 至 90 天、91 至 180 天、超过 180 天和时长未知分组。请在相近时间组内查看互动数；日期缺失或顺序不合理时，先补正资料再解释结果。

关键词与主题需要人工核验

关键词、词频或规则匹配的主题只是定位材料的线索。请回看原文和上下文，人工核验主题、情绪与研究编码后再用于论文或报告。相关表达不自动构成因果证据。

原始冻结基线保留旧项目的样本入选标记，纳入冻结导出不表示每条内容已经人工核验。招聘讨论、岗位识别误差及采集片段仍需在研究编码时核对。评论主题统计采用多标签，评论者是否为求职者尚未逐一确认。

05　招聘帖文案打分器

Job Post Checker 完全在当前浏览器中运行，不联网、不调用外部接口。输入标题和正文后，页面会返回综合编辑分、三项分项分、分项反馈和可复制的结构示例。

三项分数

互动证据分只使用当前样本里较稳定的结构线索。信息完整度分检查薪资、办公方式、Visa、资格、福利和申请路径。可读性分检查标题长度、分段、行业黑话、超长未分段和纯硬广短帖。

不要把分数当因果预测

样本不是随机试验。具体薪资、Remote 与 Visa 在当前数据中没有稳定正向互动关系，因此只进入信息完整度；黑话和长文也没有表现为低互动，因此只进入可读性检查。

06　云端汇总、备份与恢复

新增帖子、评论、审核事件和冻结报告会同步到 Firebase Firestore，并在当前浏览器保留缓存。其他成员刷新页面或重新打开站点后即可看到全组记录。首次进入新版时，旧浏览器中的新增记录会自动迁移到共享数据库。

站点不设账号、角色或写入权限限制。任何访问者都能查看共享数据、提交记录并执行通过或退回；每项操作保留匿名别名和时间。云端采用追加式记录，不提供物理删除。恢复连接后，离线期间保存在本机的改动会自动尝试上传。

完成重要导入或审核后，仍应导出 JSON 备份并保存到受控位置。CSV 用于表格查看和交换数据；需要完整恢复工作台状态时，使用 JSON 备份。

  1. 恢复前，先导出当前工作区的 JSON 备份。
  2. 在工作台选择恢复备份，读取本工作台导出的 JSON 文件。
  3. 恢复后检查记录、审核状态、版本选择和样本统计，再继续编辑。

备份文件可能包含导入的文本与来源。不要公开上传含私人信息或尚未脱敏的备份，也不要将恢复成功当作材料真实性已得到验证。

07　使用你有权处理的资料

只导入你有权处理的公开资料或已获授权材料。以作者代号代替真实身份，去除姓名、头像、邮箱、电话、私人聊天及其他敏感个人信息。对外展示研究时，使用进一步脱敏的摘录与汇总。
